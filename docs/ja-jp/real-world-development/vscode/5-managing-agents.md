GitHub Copilot をエージェント モードにすると、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat は、作業がローカル マシンでリアルタイムに行われるため、ツールの呼び出しやファイル編集の状況を逐次表示します。エディターを離れずに、各差分を確認して個別の変更を承認または取り消し、追加のプロンプトで会話を導き、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示を追加し、ハイ コントラストに加えてライト モードの切り替えを依頼します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライト モードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度試してもらいます。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められると、エージェントは一時停止して **Allow** を表示します。許可するコマンドを確認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは前の作業のコンテキスト（変更したコンポーネント、使用したスタイル設定方法、設定したローカル ストレージのパターンなど）を保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. 追加される編集を一つずつレビューし、これまでと同様に差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方針に進んだ場合（たとえば、好みでない方法で切り替え UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を補う追加プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すより速く作業を進められます。追加プロンプトで、調整（「CSS を簡潔にし、セレクターを重複させず CSS 変数を使う」）、方針の修正（「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」）、範囲の拡張（「両方の切り替えにキーボード ショートカットも追加する」）を依頼できます。

## 作業ファイルをレビューする

作業をコミットする前に、エージェントが変更したファイルをすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指定したアクセシビリティの手法（ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージでの設定保持など）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って進行中のセッションを監視し、指示を追加しました。ファイル編集を確認し、変更を承認または取り消し、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を承認または取り消す方法。
- セッションの途中で追加プロンプトを使ってエージェントを導く方法。
